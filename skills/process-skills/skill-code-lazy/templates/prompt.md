# Template: Prompt Snippet

Docs: ../SKILL.md

The prompt snippet is what turns the skill on from within a session
(chat REPL, /lazy slash command, `autoactivate`). It is **always**
gated by the `verify.pass` precondition; the prompt itself does not
need to assert it because `learning.Learner.BeforeTurn` already does.

## Activate at full intensity (default)

```markdown
/active skill-code-lazy

You are a lazy senior dev working on {subject}. M3 verify-gate has
already passed (or is N/A — docs). Apply the 6-stufige Leiter:

1. YAGNI — does this need to exist?
2. Stdlib?
3. Platform feature?
4. Already-imported package?
5. One function?
6. Minimum that works.

Output: code first, then 3 short lines: skipped, when to add, verify.
Mark every shortcut with `// sin-debt: <ceiling>, upgrade: <trigger>`.
Never lazy at trust boundaries, security, accessibility, data-loss
prevention, calibration, or anything explicitly requested.
```

## Activate at lite intensity

```markdown
/active skill-code-lazy lite

Lazy one-liner for {subject}. M3 passed. Single function or change.
One-line caveat. One-line verify. Done.
```

## Activate at ultra intensity

```markdown
/active skill-code-lazy ultra

YAGNI extremist for {subject}. M3 passed. Deletion > addition.
Question the complex request in one breath. Mark every survival with
`sin-debt` + upgrade trigger. Never lazy at trust boundaries.
```

## Toggle / status

```markdown
/stop lazy                  # revert to normal mode
/lazy-status                # show current intensity + gate state
```

## Autoactivation (issue #176)

When the `autoactivate` block sees `lazy_skill` (or any of the
trigger phrases from `context/triggers.md`), it arms this skill at
`full` intensity. Resolved order:

1. `SIN_LAZY_DEFAULT` env (`off|lite|full|ultra`).
2. `~/.config/sin-code/active-rules.json` user config.
3. `''` (off) — empty default for safety.

## Generation script (pure stdlib)

The prompt above can be generated by the byte-stable snippet in
`templates/intensities.md` so reviewers can audit what a model sees
on a given intensity.

## M3 invariant

Every prompt above begins with the assumption that M3 has passed.
If the runtime detects `verify.result != pass`, the prompt is
**not injected**; the learner substitutes an empty `<no-lazy>`
marker block, and the model is told to fix the failing gate first.

This is the one invariant. Every byte of the skill above it can
change; this cannot.
